# راهنمای نصب برنامه‌ی جمال روی سرور (VPS)

این راهنما برای کسی نوشته شده که تا حالا با سرور کار نکرده است.
هر جا دستوری داخل کادر خاکستری آمده، همان را **کپی** کنید و در پنجره‌ی سرور **Paste** کنید و Enter بزنید.

---

## ۱) چه سروری بخرم؟

از یک شرکت ایرانی (مثل آروان‌کلاد، ایران‌سرور، پارس‌پک، ابرآمد یا هر شرکت معتبر دیگر) یک **سرور مجازی (VPS)** با این مشخصات بخرید:

| مورد | مقدار |
|---|---|
| سیستم‌عامل | **Ubuntu 24.04** یا **Ubuntu 22.04** |
| حافظه (RAM) | حداقل **۲ گیگابایت** |
| پردازنده (CPU) | ۱ یا ۲ هسته |
| دیسک | ۲۰ تا ۴۰ گیگابایت (SSD بهتر است) |
| IP | یک **IPv4 عمومی** |
| دسترسی | کاربر **root** و رمز آن |

چرا حداقل ۲ گیگابایت؟ ساختن برنامه و ساختن فایل PDF فاکتور (با مرورگر Chromium) حافظه‌ی زیادی می‌خواهد. با ۱ گیگابایت معمولاً شکست می‌خورد.

بعد از خرید، شرکت این سه چیز را به شما می‌دهد (معمولاً در ایمیل یا پنل): **IP سرور**، نام کاربری **root** و **رمز**.

> اگر پنل شرکت «فایروال» یا «گروه امنیتی» دارد، پورت‌های **22**، **80** و **443** را در آن باز کنید.

---

## ۲) وصل شدن به سرور

### روش ساده: PowerShell ویندوز
1. دکمه‌ی Start ویندوز را بزنید، بنویسید `PowerShell` و آن را باز کنید.
2. این دستور را بزنید (به‌جای `1.2.3.4` آی‌پی سرور خودتان را بنویسید):

```
ssh root@1.2.3.4
```

3. بار اول می‌پرسد `Are you sure you want to continue connecting?` ، بنویسید `yes` و Enter.
4. رمز root را بنویسید و Enter بزنید. **موقع تایپ رمز هیچ چیزی روی صفحه دیده نمی‌شود؛ این طبیعی است.**
5. اگر چیزی شبیه `root@...:~#` دیدید، وصل شده‌اید.

برای Paste کردن در PowerShell کافی است **کلیک راست** کنید.

### روش دیگر: PuTTY
برنامه‌ی PuTTY را نصب کنید، در قسمت Host Name آی‌پی سرور را بنویسید، Open را بزنید، با `root` و رمز وارد شوید. (در PuTTY هم Paste با کلیک راست است.)

---

## ۳) (اختیاری ولی پیشنهادی) دامنه

اگر دامنه دارید (مثلاً `example.ir`)، سایت با **https** و قفل سبز باز می‌شود. اگر ندارید، سایت با `http://آی‌پی-سرور` باز می‌شود و مشکلی نیست.

**قبل از نصب** در پنل دامنه (مثلاً پنل ایرنیک یا هر جا دامنه را خریده‌اید، یا پنل DNS آروان/کلودفلر) یک رکورد بسازید:

| نوع | نام | مقدار |
|---|---|---|
| A | `@` (یعنی خود دامنه) | IP سرور |

اگر از آروان‌کلاد یا کلودفلر برای DNS استفاده می‌کنید، **پروکسی (ابر نارنجی/حالت CDN) را خاموش کنید** تا گواهی HTTPS گرفته شود.
تغییر DNS ممکن است از چند دقیقه تا چند ساعت طول بکشد.

---

## ۴) نصب (فقط یک دستور)

بعد از وصل شدن به سرور، **یکی** از این دو دستور را کامل کپی و Paste کنید:

**با دامنه** (به‌جای `example.ir` دامنه‌ی خودتان را بنویسید):

```
apt-get update && apt-get install -y git && git clone https://github.com/MrAbol777/jamal.git /opt/jamal && bash /opt/jamal/deploy/install.sh example.ir
```

**بدون دامنه:**

```
apt-get update && apt-get install -y git && git clone https://github.com/MrAbol777/jamal.git /opt/jamal && bash /opt/jamal/deploy/install.sh
```

نصب بار اول **۱۵ تا ۴۰ دقیقه** طول می‌کشد (بستگی به سرعت اینترنت سرور دارد). پنجره را نبندید.
در پایان پیامی با عنوان «نصب با موفقیت تمام شد» و آدرس برنامه می‌بینید.

اگر نصب وسط کار قطع شد یا خطا داد، **همین دستور را دوباره بزنید**؛ اما اگر پوشه‌ی `/opt/jamal` از قبل ساخته شده، فقط این را بزنید:

```
bash /opt/jamal/deploy/install.sh example.ir
```

(یا بدون دامنه: `bash /opt/jamal/deploy/install.sh`)
اجرای دوباره بی‌خطر است و داده‌ها پاک نمی‌شوند.

نصب‌کننده این کارها را خودش انجام می‌دهد: بررسی اینترنت سرور و انتخاب میرور مناسب برای ایران، نصب Docker، ساخت swap، روشن کردن فایروال، ساخت رمزهای تصادفی، ساخت و اجرای برنامه، ساخت کاربر مدیر و تنظیم پشتیبان‌گیری شبانه.

---

## ۵) اولین ورود

نام کاربری و رمز اولیه در یک فایل روی سرور ذخیره شده است. برای دیدنش:

```
cat /opt/jamal/ADMIN-LOGIN.txt
```

1. آدرس برنامه را در مرورگر باز کنید (`https://example.ir` یا `http://آی‌پی-سرور`).
2. با نام کاربری `admin` و رمزی که در فایل بود وارد شوید.
3. **فوراً** از صفحه‌ی «تنظیمات» رمز را به یک رمز قوی و جدید تغییر دهید.
4. بعد از تغییر رمز، فایل را پاک کنید:

```
rm /opt/jamal/ADMIN-LOGIN.txt
```

---

## ۶) انتقال اطلاعات از سیستم قبلی

اگر قبلاً برنامه را جای دیگری (مثلاً روی اینترنت/Render) استفاده می‌کردید:

1. در **سیستم قدیمی** وارد شوید، به «تنظیمات» بروید و **«دانلود نسخه پشتیبان»** را بزنید. یک فایل `backup-...json` دانلود می‌شود.
2. در **سرور جدید** وارد شوید، به «تنظیمات» بروید و در بخش **«بازگردانی نسخه پشتیبان»** همان فایل JSON را انتخاب و بارگذاری کنید.
3. این کار فقط روی سیستم تازه و خالی انجام می‌شود (اگر در سیستم جدید مشتری، محصول یا فاکتوری ثبت کرده باشید، قبول نمی‌کند). پس **اول اطلاعات را منتقل کنید، بعد شروع به کار کنید.**
4. کاربر و رمز ورود با این فایل منتقل نمی‌شود؛ همان کاربر `admin` سرور جدید را استفاده کنید.

---

## ۷) پشتیبان‌گیری (خیلی مهم)

دو نوع پشتیبان دارید؛ **هر دو را نگه دارید**:

| نوع | چطور ساخته می‌شود | کجا |
|---|---|---|
| **پشتیبان خودکار دیتابیس** (`.sql.gz`) | هر شب ساعت ۲:۳۰ خودکار | روی خود سرور: `/var/backups/jamal` |
| **پشتیبان JSON برنامه** | خودتان از «تنظیمات ← دانلود نسخه پشتیبان» | روی کامپیوتر شما |

- پشتیبان خودکار: ۱۴ روز آخر + آخرین پشتیبان هر ماه تا ۶ ماه نگه داشته می‌شود. قبل از هر به‌روزرسانی و بازگردانی هم یک پشتیبان جدا گرفته می‌شود.
- پشتیبان JSON: ساده‌ترین راه است و روی هر سیستم تازه‌ای قابل بارگذاری است. **هفته‌ای یک بار** دانلودش کنید.

### حتماً پشتیبان‌ها را از سرور بیرون بیاورید

اگر دیسک سرور خراب شود یا شرکت سرور مشکل پیدا کند، پشتیبانی که فقط روی همان سرور است هم از بین می‌رود.
**هر هفته** پشتیبان‌ها را روی کامپیوتر خودتان (و ترجیحاً یک فلش یا فضای ابری) کپی کنید.

**روش ۱: برنامه‌ی WinSCP (ساده و گرافیکی)**
1. WinSCP را از سایت رسمی آن نصب کنید.
2. File protocol: `SFTP` ، Host name: آی‌پی سرور، User name: `root` ، Password: رمز root ← Login.
3. در سمت راست به پوشه‌ی `/var/backups/jamal` بروید.
4. فایل‌های جدید را به یک پوشه در سمت چپ (کامپیوتر خودتان) بکشید.

**روش ۲: PowerShell** (روی کامپیوتر خودتان، نه داخل سرور)

```
mkdir D:\jamal-backups
scp "root@1.2.3.4:/var/backups/jamal/*.sql.gz" D:\jamal-backups\
```

### پشتیبان دستی همین حالا

```
bash /opt/jamal/deploy/backup.sh manual
```

---

## ۸) بازگردانی از پشتیبان دیتابیس

فقط وقتی لازم است که اطلاعات خراب یا اشتباهی پاک شده باشد. **همه‌ی اطلاعات فعلی با محتوای فایل جایگزین می‌شود** (قبلش خودکار یک پشتیبان ایمنی گرفته می‌شود).

فهرست پشتیبان‌ها:

```
ls -lh /var/backups/jamal
```

بازگردانی (نام فایل را از فهرست بالا بردارید):

```
bash /opt/jamal/deploy/restore.sh /var/backups/jamal/jamal-2026-01-15-0230.sql.gz
```

از شما می‌خواهد کلمه‌ی `YES` را با حروف بزرگ بنویسید. بعد از آن برنامه چند دقیقه خاموش می‌شود و دوباره بالا می‌آید.

اگر فایل پشتیبان روی کامپیوتر شماست، اول با WinSCP آن را به پوشه‌ی `/var/backups/jamal` سرور بفرستید و بعد همین دستور را بزنید.

---

## ۹) به‌روزرسانی برنامه

وقتی نسخه‌ی جدیدی آماده شد:

```
bash /opt/jamal/deploy/update.sh
```

این دستور: اول پشتیبان می‌گیرد، نسخه‌ی جدید را از GitHub می‌گیرد، برنامه را دوباره می‌سازد و بررسی می‌کند سالم بالا آمده باشد.
**اگر نسخه‌ی جدید سالم بالا نیاید، خودکار به نسخه‌ی قبلی برمی‌گردد.**

اگر بعد از به‌روزرسانی مشکلی دیدید و خواستید دستی به نسخه‌ی قبل برگردید:

```
bash /opt/jamal/deploy/update.sh --rollback
```

---

## ۱۰) دیدن وضعیت و لاگ‌ها

وضعیت کلی (سرویس‌ها، آخرین پشتیبان، فضای دیسک، حافظه):

```
bash /opt/jamal/deploy/status.sh
```

لاگ برنامه (برای فرستادن به پشتیبان فنی):

```
bash /opt/jamal/deploy/logs.sh app
```

لاگ‌های دیگر: `bash /opt/jamal/deploy/logs.sh caddy` (وب‌سرور و HTTPS) و `bash /opt/jamal/deploy/logs.sh db` (دیتابیس).
گزارش نصب: `/var/log/jamal-install.log` — گزارش پشتیبان‌گیری: `/var/log/jamal-backup.log`

بررسی دوباره‌ی اینترنت سرور (کدام سرویس‌ها باز هستند):

```
bash /opt/jamal/deploy/preflight.sh
```

## ۱۱) اضافه یا حذف کردن دامنه بعد از نصب

اضافه کردن دامنه (اول رکورد A را طبق بخش ۳ بسازید):

```
bash /opt/jamal/deploy/install.sh example.ir
```

برگشت به حالت بدون دامنه:

```
bash /opt/jamal/deploy/install.sh --no-domain
```

## ۱۲) مشکلات رایج

### دریافت ایمیج داکر ممکن نیست (Docker Hub از ایران بسته است)
نصب‌کننده خودش این را بررسی می‌کند و اگر Docker Hub بسته باشد از میرورهای ایرانی (مثل `docker.arvancloud.ir`) استفاده می‌کند. اگر باز هم خطا داد:

1. ببینید کدام میرورها کار می‌کنند: `bash /opt/jamal/deploy/preflight.sh`
2. بعضی شرکت‌های سرور، میرور داکر مخصوص خودشان را دارند؛ آدرسش را از پشتیبانی شرکت بپرسید. سپس نصب را با آن اجرا کنید (آدرس نمونه را عوض کنید):

```
DOCKER_MIRRORS="https://mirror.example.com" bash /opt/jamal/deploy/install.sh
```

3. یا پیشوند ایمیج را دستی بگذارید. فایل تنظیمات را باز کنید:

```
nano /opt/jamal/deploy/.env
```

خط `IMAGE_PREFIX=` را مثلاً به یکی از این‌ها تغییر دهید (حتماً با `/` تمام شود)، با `Ctrl+O` و Enter ذخیره و با `Ctrl+X` خارج شوید و نصب را دوباره اجرا کنید:

```
IMAGE_PREFIX=docker.arvancloud.ir/
IMAGE_PREFIX=docker.arvancloud.ir/library/
```

(اگر یکی کار نکرد دیگری را امتحان کنید. ایمیج‌های رسمی داکر زیر مسیر `library/` هستند و بعضی میرورها فقط با آن کار می‌کنند.)

### ساخت برنامه با خطای npm یا prisma یا timeout شکست می‌خورد
یعنی سرور به مخزن بسته‌های npm دسترسی ندارد یا خیلی کند است. در `/opt/jamal/deploy/.env` این خطوط را بگذارید و نصب را دوباره اجرا کنید:

```
NPM_REGISTRY=https://registry.npmmirror.com
PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma
DEBIAN_MIRROR=http://mirror.arvancloud.ir/debian
```

### سایت باز نمی‌شود
- در پنل شرکت سرور، فایروال/گروه امنیتی را بررسی کنید: پورت‌های **80** و **443** باید باز باشند.
- `bash /opt/jamal/deploy/status.sh` را بزنید و ببینید هر سه سرویس `db`، `app`، `caddy` روشن (Up) هستند.

### با دامنه، HTTPS کار نمی‌کند (خطای گواهی)
- معمولاً یعنی رکورد A دامنه هنوز به IP سرور اشاره نمی‌کند یا پروکسی/CDN روشن است. بخش ۳ را دوباره ببینید.
- بعد از درست شدن DNS، Caddy چند دقیقه بعد خودش دوباره تلاش می‌کند. برای دیدن جزئیات: `bash /opt/jamal/deploy/logs.sh caddy`

### ساختن PDF شکست می‌خورد یا برنامه مدام ری‌استارت می‌شود
معمولاً کمبود حافظه است. با `free -h` ببینید swap فعال است (ردیف Swap صفر نباشد). اگر نیست، نصب را دوباره اجرا کنید تا swap ساخته شود. اگر سرور اجازه‌ی swap نمی‌دهد، سرور را به RAM بیشتر (۳ یا ۴ گیگابایت) ارتقا دهید.

### دیسک پر شده است
`bash /opt/jamal/deploy/status.sh` را ببینید. پشتیبان‌های قدیمی خودکار پاک می‌شوند؛ اگر باز هم پر است، فضای دیسک سرور را بیشتر کنید.

---

## ۱۳) چک‌لیست امنیت

- [ ] رمز `admin` را بعد از اولین ورود عوض کرده‌ام و فایل `ADMIN-LOGIN.txt` را پاک کرده‌ام.
- [ ] رمز root سرور قوی است و آن را جای امنی (نه در پیام‌رسان) نگه داشته‌ام. (بهتر: ورود با کلید SSH.)
- [ ] پشتیبان‌ها را هر هفته روی کامپیوتر خودم کپی می‌کنم. پشتیبان‌ها شامل همه‌ی اطلاعات مشتری‌ها هستند؛ آن‌ها را به کسی نمی‌دهم.
- [ ] فایل `/opt/jamal/deploy/.env` رمز دیتابیس و کلید ورود را دارد؛ آن را به کسی نمی‌دهم و هرگز در GitHub قرار نمی‌گیرد.
- [ ] سیستم‌عامل خودکار به‌روزرسانی امنیتی می‌شود؛ هر چند ماه یک بار سرور را ری‌استارت می‌کنم (`reboot`؛ برنامه خودش دوباره بالا می‌آید).

## ۱۴) چند هشدار مهم

- پوشه‌ی **`/var/lib/jamal`** خود دیتابیس است. **هرگز** آن را پاک نکنید.
- دستورهایی مثل `docker compose down -v` یا `docker system prune --volumes` را **نزنید**.
- فایل `/opt/jamal/deploy/.env` را تغییر ندهید، مگر طبق همین راهنما (به‌خصوص `DB_PASSWORD` را هرگز عوض نکنید).
